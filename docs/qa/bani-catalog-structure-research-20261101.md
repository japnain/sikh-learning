## Provider contracts that block a generic splitter

1. `header=2` is evidence of a printed structural row, not a universal shabad boundary. It can be an umbrella title, metre, author, house, instruction or summary count. Conversely, some true divisions have no repeated heading.
2. The provider `paragraph` field is not a reliable composition-unit count. For example, 52 has 10 paragraph groups but six main numbered stanzas;42 has six paragraph groups but three cycles of eight printed stanzas.
3. Inner `verseId` is a **bani-local observed locator**, not a proven global scripture verse ID. Reading order must use row order. IDs 84 and 85 start with higher-numbered mangal rows before their lower-numbered main headings.
4. Refrains, colophons, cumulative totals and reset numbering require explicit handling. Numbered-looking ends do not by themselves justify Pauri, Salok, Savaiyya or Shabad labels.
5. Catalog source/range descriptions do not override actual loaded text. Collections 1, 32, 36, 55, 67 and the mixed daily prayers demonstrate this sharply. Display attribution only at the scope supported by the text/provider evidence.
6. Variant flags are retained because 21/23 must be evaluated through the **actual selected normalized output**, not the longest raw payload. All future navigation must confirm both anchor identity and expected text against the loaded version.
