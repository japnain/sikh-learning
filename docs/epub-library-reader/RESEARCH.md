# EPUB Library Reader Research

## Objective

Replace the Panth-Prakash-only OCR dump with a reusable, safe EPUB publishing pipeline and a focused reader. The first collection is *Sri Gur Panth Prakash*, using the two supplied Internet Archive EPUBs. Future curated EPUBs must be addable without rewriting the app or replacing the existing catalog.

## Current-state audit

- The current importer is hard-coded to one work, two volumes, magic page offsets, and one manually maintained episode seed.
- Every import overwrites `works.json` and `search-index.json`, so a second book would erase the first one.
- EPUB XHTML is flattened into giant plain-text paragraphs. Source filenames and internal EPUB page numbers are exposed in the reading UI.
- Reading progress stores only a chapter path; the displayed percentage is chapter ordinal rather than an exact reading location.
- The overview eagerly loads a multi-megabyte whole-book search index.
- The current renderer is React text, which is safe, but it has no reusable publication/volume model, semantic verse blocks, reader settings, TOC drawer, or stable locator contract.

Both files are EPUB 3.0 archives generated by Internet Archive `hocr-to-epub`. Both have empty navigation, a nonexistent cover reference, missing bibliographic metadata, invalid `lang="None"`, and one enormous OCR paragraph for nearly every scanned page. Neither contains an image, cover, embedded font, or scan page. There are exactly zero Unicode Gurmukhi characters in either archive.

The print edition is a facing-page bilingual layout. The screenshot supplied by the user confirms English translation on the left and Gurmukhi/transliteration on the right. The EPUB conversion flattened this into alternating spine items. The odd English pages are substantially readable; the even source pages contain Roman transliteration mixed with failed Gurmukhi OCR and must not be presented as authentic Punjabi.

Recovered edition metadata:

- Title: *Sri Gur Panth Prakash*
- Author: Rattan Singh Bhangoo
- English translator: Kulwant Singh
- Publisher: Institute of Sikh Studies, Chandigarh
- Volume I: 2006, ISBN 81-85815-28-3
- Volume II: 2010, ISBN 81-85815-31-3

## Runtime-engine spike

### foliate-js

Foliate has strong EPUB features, but its own README describes the API as unstable and unreleased. Its WebKit iframe enables scripts and same-origin access and explicitly requires a strong content-security policy. This app does not currently have that CSP, so it is not an acceptable production dependency for curated content.

### epub.js

epub.js provides CFI locations, pagination, TOC support, and a no-script iframe by default. It would still faithfully render the malformed OCR XHTML, and its current npm line carries an old XML dependency unless overridden. It also makes whole-book search section-by-section. It remains a possible future adapter for raw local uploads, not the canonical curated reader.

### Chosen approach

Use a sanitized build-time publication pipeline and a first-party React scrolled reader:

1. Preserve original EPUB bytes, hashes, and provenance.
2. Parse the EPUB container, OPF, spine, and navigation during import.
3. Convert XHTML into a small semantic block schema. Never render imported markup with `dangerouslySetInnerHTML`.
4. Generate per-work catalog, TOC, content, positions, and lazy search assets.
5. Model locations with a Readium-shaped locator so another rendering engine can be added without changing progress data.
6. Apply an explicit `panth-prakash-english` normalization profile to these two OCR archives: select the readable English leaves, split episodes inside pages, restore meter/verse structure, strip running furniture, and retain source page locators.

This is the smallest architecture that fixes the supplied books and remains reusable. It also prevents untrusted EPUB scripts, remote resources, malformed tags, and CSS from entering the app document.

## Product decisions

- The default Panth Prakash experience is a clean English reading edition.
- The UI explains that the supplied EPUB source OCR cannot provide trustworthy Gurmukhi. It does not silently present corrupted Latin symbols as Punjabi.
- Volume I and II are publications inside one collection, not two unrelated books.
- The focused reader hides the primary app navigation and prioritizes title, progress, contents, display settings, and next/previous movement.
- Internal EPUB filenames and raw page chips stay in provenance, not reading chrome.
- Search assets load only after a search is requested.
- New curated books are added through one import command that merges catalog entries. Personal in-app file uploads and cloud storage are a later product phase because they require local persistence, quota handling, moderation, and a separate trust boundary.
